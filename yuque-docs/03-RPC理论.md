# 3. RPC理论

## 什么是RPC?

RPC全称为Remote Procedure Call —— 远程过程调用。

我们先看最简单的函数调用：

```go
// 这叫本地函数调用, 因为这个函数其实就在你的程序里面
result := Add(1, 2)
```

而RPC,其实就是像调用本地函数一样，调用另一台机器上的函数。

```go
// 看起来调用方式和第一种调用方式完全相同,但实际上这个函数其实在别的服务器上
result := client.InvokeAsync("Arith", "Add", 1, 2)
```

内部也封装了一些操作, 如：
- 通过网络发送请求
- 对方计算完再返回结果

在项目代码中,客户端调用方式如下:利用InvokeAsync函数,将函数所需要的参数(args)提前准备好, 并指定需要调用的服务(Arith)以及对应服务上的具体某一个函数(Add)

而函数背后所做的事情是:

1. 客户端把：服务名（Arith）方法名（Add）参数（1,2）序列化通过 TCP 发给服务器
2. 服务端通过反射找到 Arith.Add并执行计算与得到结果, 再将结果再发回客户端
3. 最后由客户端解析结果

所以可以理解为简单的RPC为：**客户端 ↔ 网络 ↔ 服务端**

## 为什么需要RPC?

在现代系统里，系统是分布式的：
- 用户系统
- 订单系统
- 支付系统
- 推荐系统

它们通常部署在不同机器上。

如果没有 RPC：每个系统之间需要手动处理网络通信、序列化、错误处理等底层细节，开发效率低且容易出错。

有了 RPC：调用远程服务就像调用本地函数一样简单，框架封装了底层通信细节。
