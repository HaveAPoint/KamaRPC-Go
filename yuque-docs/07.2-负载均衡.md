# 7.2 负载均衡

## 为什么需要负载均衡?

在后端系统中, 如果只有一台服务器, 那么所有的请求都打到这台机器。当访问量变大的时候,会出现响应变慢、CPU 爆满、内存打满。

所以我们一般会部署多台服务器, 把请求分发给不同的机器——这是需要负载均衡的原因。

在多个服务实例之间，合理地分配请求流量。比如你有 3 台服务 A、B、C, 客户端每次发请求时，需要决定：发给 A？还是发给 B？还是发给 C？这个选择规则,就是负载均衡算法。

## 负载均衡代码讲解

结合项目中的负载均衡来看,有三种算法,他们都实现了 `Select` 这个接口的方法。

### 统一接口定义

```go
// internal/loadbalance/balancer.go
type LoadBalancer interface {
    Select([]registry.Instance) registry.Instance
}
```

### 随机算法

最简单的方式之一, 每次随机选一个, 优点简单实现容易。但是缺点就是短时间可能全打到同一台服务器。

```go
// internal/loadbalance/random.go
type Random struct {
    r *rand.Rand
    m sync.Mutex
}

func NewRandom() *Random {
    return &Random{
        r: rand.New(rand.NewSource(time.Now().UnixNano())),
    }
}

func (r *Random) Select(list []registry.Instance) registry.Instance {
    if len(list) == 0 {
        return registry.Instance{}
    }
    r.m.Lock()
    defer r.m.Unlock()
    return list[r.r.Intn(len(list))]
}
```

### 轮询算法

针对上述所说的3台服务器,利用轮询算法。那么会按照顺序的一个一个选。

优点是非常均匀、简单稳定。但是这种缺点也很明显,就是没有考虑到机器之间性能的差异。假设A服务器性能更高,那么理应它的承受能力也是最高的, 更多请求应该分配给它。

```go
// internal/loadbalance/round_robin.go
type RoundRobin struct {
    idx uint64
}

func (r *RoundRobin) Select(list []registry.Instance) registry.Instance {
    i := atomic.AddUint64(&r.idx, 1)
    return list[i%uint64(len(list))]
}
```

> 使用 `atomic.AddUint64` 保证并发安全，无需额外加锁。

所以这也就有了下面的加权轮询算法。

### 加权轮询算法（重点）

如果A机器很强,而B一般,C很弱,那么我们可以设置权重。

例如此时,由于A占比为5/9, 那么每9次,按道理会出现5次, 而B是3次, C是1次。

```go
// internal/loadbalance/weighted_rr.go
type WeightedRR struct {
    mu            sync.Mutex
    weights       []int // 固定权重
    currentWeight []int // 当前权重（动态变化）
    totalWeight   int   // 权重总和
}

func NewWeightedRR(weights []int) *WeightedRR {
    w := &WeightedRR{
        weights:       make([]int, len(weights)),
        currentWeight: make([]int, len(weights)),
    }
    copy(w.weights, weights)
    total := 0
    for _, wt := range weights {
        if wt < 0 { wt = 0 }
        total += wt
    }
    w.totalWeight = total
    return w
}

func (w *WeightedRR) Select(list []registry.Instance) registry.Instance {
    if len(list) == 0 {
        return registry.Instance{}
    }
    w.mu.Lock()
    defer w.mu.Unlock()

    maxIdx := -1
    // 所有节点 currentWeight += weight
    for i := 0; i < len(list); i++ {
        w.currentWeight[i] += w.weights[i]
        if maxIdx == -1 || w.currentWeight[i] > w.currentWeight[maxIdx] {
            maxIdx = i
        }
    }
    // 选中最大权重节点
    w.currentWeight[maxIdx] -= w.totalWeight
    return list[maxIdx]
}
```

> **平滑加权轮询核心思想**：每轮给所有节点累加各自的静态权重，选出 currentWeight 最大的节点，然后减去 totalWeight。这样权重高的节点被选中的次数多，且分布平滑，不会连续全打在同一节点上。
