# 7.5 熔断

## 什么是熔断?

举个生活的例子: 一个电路设备过载或者电流过大的时候,熔断器会跳闸,暂时停止供电。

而RPC中也是一样的,服务连续失败的时候,熔断器就会打开,暂停请求一段时间,防止错误不断放大。

举例: 服务 A 调用 服务 B, 但是 B 已经挂了,而 A 还在疯狂重试——这会导致线程堆积、连接池耗尽、A 也被拖死。**这叫做雪崩效应**。

## 熔断代码封装讲解

### 熔断器的三种状态

熔断器有三种状态：
- **Closed（关闭）**：正常状态，请求正常通过
- **Open（打开）**：熔断状态，拒绝所有请求
- **HalfOpen（半开）**：探测状态，只允许一个请求通过来试探服务是否恢复

### 结构体定义

熔断器结构体包含如下数据：

- `failureCount` 和 `successCount`：用来计算错误率,当达到一定错误率的时候,熔断器会开启,拒绝请求
- `windowSize`：表示至少统计多少次请求,才会开始计算错误率。如果不设置这个,那么第一次就调用失败了,错误次数和调用次数都是1,那么错误率将会达到百分百,就直接开启熔断了,这不合理。所以需要设置一个值,表示达到这个值了,才开始进行错误率判断。
- `failureThreshold`：错误率阈值。例如 0.6, 表示当错误率达到 60% 的时候,熔断就会开启。

### Allow() 方法

表示是否允许请求通过：
- 当 **Closed** 时候,表示熔断器关闭,允许通过
- **Open** 就相反了,表示熔断器开启了,不允许通过
- 而 **HalfOpen** 状态,此时只会允许一个探测请求,如果这个探测请求成功,那么会将熔断器关闭。通过 `halfOpenProbe` 字段维护, 避免半开阶段被大量请求冲垮。

### 熔断器的状态切换

Closed → (错误率超阈值) → Open → (超时后) → HalfOpen → (探测成功) → Closed
